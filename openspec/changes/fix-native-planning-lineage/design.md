# Design: Two authenticated lineage relationships

Protected context independently authenticates root identity, signatures, exact-root Requirements and
member authority, regular planning scope and current protected control objects. Its planning_base_commit
is an authenticated proposal boundary; proof_base_commit remains the validator trust boundary.

Native stack github.base_ref is dev even when the REST child base is the runtime parent's branch.
Compare proof-base ancestry to the immutable review merge base, and separately compare evidence-base
ancestry to the candidate. Validate both identities. Without a planning override the evidence base is the
proof base, preserving ordinary validation. No check, provider pin, signature or scope control is disabled.

Exercise the actual workflow shell preflight in isolated real Git histories. Controls cover ordinary and
native planning ancestry, unrelated trust, unrelated planning and evidence newer than the candidate.
Test bytes remain immutable from native RED through GREEN. Rollback restores the coherent workflow/version
patch and captured heads; children remain blocked until reviewed protected integration and revalidation.
