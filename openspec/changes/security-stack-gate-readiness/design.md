# Gate-preserving stack readiness

Keep full native plan equality. A native stack context identifies its live root
PR and protected dev/main base; it does not rewrite a RED report or add a passing
case to RED. Authenticate every parent edge against GitHub native stack identity,
position, size, repository, exact branch/head and commit ancestry. Revalidate live
metadata in all consumers; missing, ambiguous, changed or forked metadata fails.
The existing provenance validator then uses the authenticated immutable root base,
original RED artifact and current source. Test/support changes remain stale proof.

Author the complete dependency scope before replaying its implementation after a
normal prerequisite integration. Mappings, executable selectors and acceptance
must stay unchanged across the five layers. A different mapping or plan remains a
hard reconciliation failure; no scoped digest relaxation is introduced.

Direct/console smoke runs receive workspace-owned virtual environments with the
complete frozen CI graph installed offline into each child. Inherited Python paths
and parent site-packages are excluded; only the explicit CLI source path is exposed. Runtime smoke independently
authenticates the reviewed portable 046d366c module snapshot; native Requirements
keeps its 69f0758 provider and original proof unchanged. Only reviewed Lz4 is
seeded from an exact hash-protected wheel lock. BasedPyright keeps the approved
npm runner; unofficial Node wheels are prohibited in every frozen graph.
Marketplace pip sees only child-installed packages with union version
constraints and no index. This
prevents upgrades in the running pytest environment and fails on missing pins. Other launcher modes retain their existing delivery
checks. Existing isolated virtualenv fallback cache controls remain intact.

Organization authority executes only immutable organization policy, never PR
bytes. Native parent branches are accepted only after API ancestry validation;
all existing unedited member-comment, exact commit/tree, seven-day expiry and
live collaborator-permission checks remain required. A prerequisite policy PR
must be reviewed and pass its own tests before integration.

Risks: parent pushes invalidate context; missing frozen module dependencies fail
closed; rebases invalidate head-bound grants and proof. Mitigate with final-head
validation, reviewed frozen inputs and new grants. Rollback uses captured heads,
explicit leases and normal revert of prerequisites; never disable required gates.

The normal pip-tools marketplace resolver also receives a child-owned wheelhouse. Its inputs are the transitive closure of authenticated, unmodified module manifests, selected from the committed frozen graph and exact hash-protected exports. Downloads require the committed hashes and wheels; resolution keeps its existing constraints and no-index policy. Missing or unreviewed graph entries fail closed. No resolver or install validation is skipped.

Ref compatibility follows Git branch naming rules in the standard-library-only adapter, while retaining traversal, reserved-sequence and option-boundary rejection. Smoke archives stage bytes from the authenticated pinned Git object instead of copying untracked or ignored checkout files. Original mapped native selectors stay frozen.

Child bundle bootstrap also points only to the owned staging tree. Raw checkout metadata remains a separate authenticated seed input; inherited bundle-root overrides are removed. This closes ignored-file imports in addition to archive contents.
