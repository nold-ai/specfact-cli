# Design

The data contract is the reviewed package/version table, two public dependency
floors and three distinct advisory records. The existing frozen refresh and audit
implementations remain the source of behavior. The existing selection test
compares nonempty SHA-256 sets from lock artifacts and exported requirements.
No new dependency resolver or advisory engine is needed.

Use a new change root because Requirements selects the complete mapping for
each changed root. Editing the delivered `isolate-semgrep-security-runtime`
mapping would incorrectly demand new RED for cases already passing on dev.
Keep that root and all historical evidence byte-identical.

Tests inspect the canonical lock/export and metadata, invoke the existing audit
gate with concrete hostile inputs, and exercise the frozen GitPython API with
the clone boundary observed. Passing preservation and negative controls run
alongside the selected genuinely failing cases but are not labeled RED.

Only scoped hunks may enter existing dev files. Preserve its third audit,
runtime-smoke graph, native artifact transport, trusted planning/proof bases and
all other runtime behavior. Reuse reviewed official artifact metadata, then
regenerate and verify the lock/export with normal tooling. Never hand-edit the
generated dependency lists to force a resolver result.

CI-only Git signing must bind the reviewed tree, exact dev parent and a new
create-only branch using existing permissions. It grants no shared-history
rewrite, protected ref change or merge. The test-only prefix must remain
separate from later production commits.

Native bootstrap is an explicit open delivery dependency. The base's expired
parser record prevents test execution; changing that production record in the
RED prefix is not a native proof fix. The concrete trusted bootstrap or exact
admission prerequisite needs independent review and any separate protected
deployment approval before adoption. No implementation is claimed here.

Rollback before merge is disposal of the unmerged candidate branch. A later
merged dependency correction can be reverted through an ordinary reviewed PR.

## Fixed prior-proof connection

The current signed test prefix has genuine native failing-first evidence.
Connect that one immutable packet through the existing late-RED transfer owner
and isolated origin workflow. The source commit and auxiliary executor are
distinct identities. All three consumers must independently authenticate the
same packet, preserve trusted C provenance and selected source bytes, and
complete their native final executions. Do not add an index, reusable bootstrap
framework or missing-native-RED waiver.

A run-identity unit regression uses a retained GitHub API replay as data. Its
fixed admission does not grant CLI transfer or adoption authority. Keep the new
route unregistered until complete packet, source signature, origin, exact final
head and fresh owner authority checks are implemented and reviewed. Protected
adoption remains a separate owner decision for a concrete reviewed candidate.
The internal wiki mirror is unavailable at the expected matching source path;
updating it and rebuilding the internal graph remains an explicit follow-up.

The fixed packet boundary accepts only the retained four native34 payloads.
It reads the aggregate plan directly and preserves the separate source plan.
Report selectors retain their sorted order. JUnit selectors retain aggregate
execution order, and every case must fail. Exact digests bind the reviewed
assertion bodies without rewriting source reports or assigning final authority.
The portable regression uses inert copies of these bytes. Public registration
remains closed during this partial unit.

The existing artifact validator takes a derived envelope containing the captured
artifact API object and signed source commit API object. The fixed variant
binds the artifact to E34 and the verified source to R2. This envelope is not
an original API response, origin proof or owner grant. Each later consumer
fetches these records independently and freezes the derived bytes before use.
Historical callers keep the same signature and do not need a source record.

The immutable C-to-R2 test prefix includes its eleven-line CHANGE_ORDER entry.
Admit only that exact metadata path for the fixed scope, while retaining the
generic historical path guard and all production-path refusals. The fixed
normalizer copies the already-bound canonical report instead of rebuilding
it. Capture and recheck its exact digest, then use unchanged C validation.
Full-history integration tests live under tests/proof. Existing full-suite CI
fetches complete history and collects them. Shallow compatibility jobs select
other directories, so no new fetch, skip or workflow is needed.

## Complete fixed-head connection

The accepted current native proof has 21 intended assertion failures at signed
R2. Its original policy-repository run and ZIP remain immutable. Core consumers
cannot assume their repository-scoped token can download that cross-repository
archive. The minimum proposed transport uses the existing CI signer to upload
only four byte-exact retained members as a separately identified core COPY.
It supplies no new native execution or full original-archive claim.

The signer must preserve every normal TEST/CODE checkpoint in order. Its
program, workflow and runtime bytes are fixed before the eventual source intent.
F pins those executable hashes; F's verified message identifies the actual
executor, raw intent digest, run and attempt. This avoids both executor/intent
and future-artifact identity cycles. Consumers validate all output checkpoints,
not only a matching final tree. Partial publication or failed upload refuses
adoption without overwriting or repeating a consumed operation.

A new isolated origin job in the existing Requirements workflow precedes the
producer and does not import candidate code under attestation credentials.
The existing late-RED entry point authenticates origin and fresh immutable f7
owner authority before private normalization. Each of the three native lanes
independently validates the retained copy and all current associations, uses
the same protected tool graph, invokes unchanged C provenance and performs
its actual final native work. Historical routes remain compatible.

This is local implementation scope, not protected deployment or final-head
approval. A concrete complete independently reviewed CI-signed F must precede
the separate exact-F owner decision, including the current retained-member
association. The original strict audit deadline is enforced by setting only
Europe/Berlin on the existing three-command CI step.
