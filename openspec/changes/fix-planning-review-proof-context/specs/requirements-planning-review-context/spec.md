## ADDED Requirements

### Requirement: Preserve finalized inherited review context

Independent and final Code Review consumers SHALL retain protected-dev Python review scope and full
enforcement. For authenticated planning children they SHALL use unchanged finalized execution proof
from the exact verified root Requirements run. Child planned evidence SHALL remain separate and SHALL
NOT be relabeled as execution. Ordinary final proof review SHALL remain available.

#### Scenario: Native planning reviews inherited runtime changes

- **GIVEN** a signed verified root with genuine final proof and a closed planning child
- **WHEN** independent or final Code Review sees inherited Python changes against protected dev
- **THEN** the immutable provider SHALL receive the authentic root finalized context
- **AND** the child planning receipt and inherited review paths SHALL remain unchanged

### Requirement: Reject inherited review context forgery

Each consumer SHALL independently reauthenticate the live native context and uniquely bind the artifact
to the successful root Requirements run, repository, branch and head. It SHALL verify expiry, archive
digest, bounded regular report identity, finalized stage and exact-root proof. Missing, stale, foreign,
ambiguous, corrupted, producer-only or planning-only evidence SHALL fail closed without fabricated proof.

#### Scenario: A planning receipt cannot authorize inherited Python review

- **GIVEN** an invalid artifact or report and a valid planning child
- **WHEN** a consumer prepares finalized review context
- **THEN** review SHALL fail before accepting that context
- **AND** valid genuine root proof SHALL still pass with all normal review gates enforced
