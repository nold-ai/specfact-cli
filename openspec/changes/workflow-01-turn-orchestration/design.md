## Risk-first guidance in the existing skills

This is a guidance amendment, not an extension to runtime/report/receipt interfaces. Keep canonical reusable guidance in modules and repository wrappers/projection in core. Reference `docs/agent-rules/INDEX.md`, `40-openspec-and-tdd.md`, `50-quality-gates-and-review.md` and `60-github-change-governance.md` rather than copying their policy. Each repository owns applicability and actual commands. Core projection references the modules-owned content; do not hand-copy a second canonical body.

| Existing skill | Added responsibility |
| --- | --- |
| `specfact-pre-validate` | Identify one or two approach-invalidating assumptions for nontrivial behavior changes; record planned observable checks, obligations and exclusions in existing sections. Use a brief applicability rationale for documentation-only work. |
| `specfact-implement` | Execute the smallest relevant existing probe before work that depends on its assumption. Record inputs/evidence and the exercised boundary. A disproved assumption returns dependent work to design; an unsupported probe leaves it unresolved. Continue independent work without presenting the dependent approach as ready. Preserve spec -> tests -> failing evidence -> code -> passing evidence. |
| `specfact-verify` | Run required verification on current bound inputs, preserving source/index bytes and independent producer outcomes. A narrow passing probe proves only its exercised boundary; failed/unavailable required producers remain non-passing. Fresh-session verification requires no earlier receipts. |
| `specfact-fix` | Triage with the violated requirement or concrete invariant, reachable failure path and supporting evidence; distinguish confirmed defects, disproved concerns, suggestions and unresolved claims. Model agreement is supporting context, never proof. Preserve producer authority and effective remediation policy. |
| `specfact-autofix` | Keep one writer, batch compatible corrections and pass compact delta/evidence handoffs within existing authority/budgets. Rebind affected verification after changes and broaden review for boundary drift or uncertain impact. Preserve exact-head external-write safeguards. |

Supply assumptions, observed evidence, affected obligations and exclusions to the applicable existing review. No additional default review lane is introduced. A confirmed required defect stays actionable; a preference may receive an evidenced disposition, but disposition cannot waive a required finding under effective governance or alter its producer's verdict. Unsupported claims remain unresolved until evidence or the owning policy supplies a decision.

Correction handoffs reuse existing notes/producer artifacts: delta, affected assumptions, remaining findings and original evidence references. They are not a new packet format. Broaden review when a public/assurance/persistence/signing/compatibility boundary changes or dependency impact is uncertain. Compact handoffs do not reduce final candidate coverage: recheck every affected gate or use identity-matching valid outputs; select the complete lane when applicability is uncertain. One controller retains consumed elapsed/attempt budgets across implementation, optional preflight and PR repair; a handoff/session cannot reset them.

## Bounded evaluation of delivery overhead

Use existing CI timings, producer artifacts and available provider/session records; introduce no ledger, report fields or automatic collection. Token counts by available category (for example input/output/cache) and actual billed charges are different measures. Elapsed time, active engineer effort and waiting are also different measures; record units, source and unavailable values as unknown. Do not convert elapsed time or tokens into labor or money without defensible data.

After the skills/projection slice, review investment at two engineer-days. Run one bounded trial on the next subsequently authorized nontrivial change per repository under existing budgets; compare early discoveries, later escapes, correction batches and observed overhead. Trials are operational evidence, not causal savings proof. Stop/reassess if added ceremony outweighs the observed benefit. Disable/revert guidance/projection if needed while preserving evidence and ordinary checks; existing runtime configuration/module-pin rollback and signed acceptance remain unchanged.
